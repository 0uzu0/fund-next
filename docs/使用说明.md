# LanFund 使用说明

本文档说明 **服务端** 的部署、配置与日常使用。

---

## 一、服务端使用说明

服务端提供 Web 前端页面与后端 API（端口 8311），支持 Docker 部署或源码运行。

### 1.1 部署方式概览

| 方式 | 适用场景 | 说明 |
|------|----------|------|
| **Docker 镜像（推荐）** | 生产 / 自建服务器 | 使用 CI 已构建好的镜像，拉取即用 |
| **本地 Docker 构建** | 无 CI 或需自定义构建 | 从源码在本地构建镜像后运行 |
| **源码运行** | 开发 / 调试 | 在本机用 Node 分别启动后端与前端 |

### 1.2 使用 Docker 镜像部署（推荐）

**前提**：已安装 Docker 与 Docker Compose。

1. 在项目根目录创建 `.env` 文件（可参考 `.env.example`）：

```env
# 镜像地址（替换为你的 GitHub 用户名与仓库名）
DOCKER_IMAGE=ghcr.io/你的用户名/fund-next:latest

# Session 密钥（必填，建议随机字符串或 UUID）
SESSION_SECRET=请替换为一串随机密钥

# 可选：时区，默认 Asia/Shanghai
TZ=Asia/Shanghai
```

2. 启动服务：

```bash
docker-compose up -d
```

3. 查看日志与状态：

```bash
docker-compose logs -f    # 查看日志
docker-compose ps         # 查看容器状态
```

4. 访问地址：

- **Web 前端**：http://服务器IP:8311（同端口，后端会托管前端静态资源）
- **健康检查**：http://服务器IP:8311/api/health

5. 停止服务：

```bash
docker-compose down
```

**说明**：数据与 Session 会持久化在 Docker 卷 `fund-data` 与目录 `backend/cache`，重启或重新 up 不会丢失。

### 1.3 本地 Docker 构建后运行

未使用 CI 或需要从源码构建镜像时：

```bash
docker-compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

同样在 `.env` 中配置 `SESSION_SECRET` 等（若使用 build 配置，可能不需要 `DOCKER_IMAGE`，以 docker-compose.build.yml 为准）。访问方式同上。

### 1.4 源码运行（开发环境）

**前置**：Node.js >= 18。

1. 安装依赖：

```bash
npm run install:all
```

2. 配置后端 `backend/.env`：

```env
DB_PATH=./cache/fund_data.db
SESSION_SECRET=你的密钥
PORT=8311
CORS_ORIGIN=http://localhost:3000
```

3. 配置前端 `frontend/.env.local`（开发时指向本地后端）：

```env
NEXT_PUBLIC_API_URL=http://localhost:8311
```

4. 启动：

```bash
npm run dev
```

- 前端：http://localhost:3000  
- 后端 API：http://localhost:8311  

5. 首次访问：打开 http://localhost:3000，若未登录会跳转登录页。默认账号：`admin` / `admin`（请及时修改）。

### 1.5 服务端环境变量汇总

| 变量 | 说明 | 示例 |
|------|------|------|
| `PORT` | 服务端口 | `8311` |
| `SESSION_SECRET` | Session 加密密钥 | 随机字符串 |
| `DB_PATH` | SQLite 数据库路径 | `./cache/fund_data.db` |
| `CORS_ORIGIN` | 允许的 Web 来源（开发时） | `http://localhost:3000` |
| `TZ` | 时区（Docker 时常用） | `Asia/Shanghai` |

### 1.6 镜像构建与发布（维护者）

- **自动**：代码 push 到 `main`/`master` 后，CI 会构建并推送 `ghcr.io/<仓库>:latest`。
- **手动**：在 GitHub Actions 中选择「CI/CD」workflow，点击 Run workflow，可选填写镜像标签（如 `v1.0.0`）。
